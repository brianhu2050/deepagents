# SubAgent Middleware Prompts 解析

`SubAgentMiddleware` 的强大之处不仅在于其任务委派的架构，更在于它通过一系列精心设计的、高度详细的 Prompt 来**教会**主智能体（Orchestrator）如何成为一个高效的“项目经理”。本文档将解析其中三个核心的 Prompt 文本。

---

## 1. `TASK_SYSTEM_PROMPT`

### 1.1. 目的与作用

这个 Prompt 是注入给**主智能体**的**战略性指导**。它不关心 `task` 工具的具体用法，而是从更高层面教会主智能体“何时”以及“为何”要委派任务。

-   **核心思想**: 建立“任务隔离”和“并发执行”的心智模型。
-   **“何时使用”清单**: 提供了一个清晰的决策框架，告诉模型在遇到以下情况时应该使用 `task` 工具：
    -   任务复杂、多步、可独立。
    -   任务可以并行，以提高效率。
    -   任务需要大量上下文（Token），隔离执行可以避免主线程“臃肿”。
    -   任务需要沙箱环境以提高可靠性（如代码执行）。
    -   只关心最终结果，不关心中间过程。
-   **“何时不用”清单**: 同样重要，它提供了“反向约束”，防止模型滥用此工具，避免在简单任务上增加不必要的开销和延迟。
-   **反复强调并发**: Prompt 多次使用“`parallelize`”、“`in parallel`”等词语，强化了**效率**是任务委派的一个核心目标。

### 1.2. 注入机制

-   在 `SubAgentMiddleware` 的 `__init__` 方法中，此 Prompt 被设为默认的 `system_prompt`。
-   在 `wrap_model_call` 方法中，它被追加到主智能体原有的系统提示之后。这是一个**几乎无条件**的注入（仅当 `self.system_prompt` 不为 `None` 时），确保主智能体始终具备任务委派的战略思想。

---

## 2. `TASK_TOOL_DESCRIPTION`

### 2.1. 目的与作用

如果说 `TASK_SYSTEM_PROMPT` 是战略指南，那么 `TASK_TOOL_DESCRIPTION` 就是一份详尽的**战术手册和操作指南**。它作为 `task` 工具自身的描述，其内容之丰富远超常规工具。

-   **动态能力清单**: 它包含一个 `{available_agents}` 占位符。在运行时，这里会被动态地替换为所有已定义的子智能体的**名称**和**描述**。这使得主智能体能确切地知道自己有哪些“专家团队”可以调用。
-   **严格的规则和期望**:
    -   **并发**: 再次强调并发。
    -   **无状态性**: 明确告知主智能体，子代理是“一次性”的，无法进行后续交互，因此初始指令必须极其详尽。
    -   **结果处理**: 指示主智能体在收到子代理的结果后，需要自己进行总结并呈现给用户。
-   **高质量的示例 (`<example>`)**: 这是此 Prompt 最精华的部分。它提供了大量带有“思维链” (`<commentary>`) 的正反面示例，手把手地教会模型在具体场景下如何推理和决策：
    -   **研究任务**: 演示了如何将一个大的研究任务分解为三个并行的子任务。
    -   **代码分析**: 演示了如何用子代理隔离一个消耗大量上下文的单一任务。
    -   **反例（订餐）**: 明确指出对于简单的、并行的工具调用，不应该使用 `task` 工具。
    -   **自定义代理用法**: 展示了如何根据子代理的“专业领域”（如 `content-reviewer`, `research-analyst`）来决定调用哪一个。

### 2.2. 注入机制

-   此文本在 `_create_task_tool` 函数中被格式化（填入子代理列表），然后作为 `description` 参数传递给 `StructuredTool.from_function`，最终成为 `task` 工具模式（Schema）的一部分。当模型“看到”`task` 工具时，这段描述就是它理解该工具如何使用的全部信息。

## 3. `DEFAULT_SUBAGENT_PROMPT`

### 3.1. Prompt 原文

```
In order to complete the objective that the user asks of you, you have access to a number of standard tools.
```

### 3.2. 目的与作用

这个 Prompt 是**子智能体**的**默认系统提示**。与前两个给主智能体的 Prompt 不同，这个是给“工人”的。

-   **简洁通用**: 它的内容非常简单和通用，因为它旨在适用于任何可能被定义的子智能体，特别是 `general-purpose` 代理。
-   **能力告知**: 它的唯一作用就是告诉子智能体：“你是一个拥有工具的代理，你的任务是完成接下来的指令”。
-   **可被覆盖**: 在定义具体的 `SubAgent` 时，可以通过 `system_prompt` 字段提供一个更具针对性的、详细的系统提示来覆盖这个默认值。例如，可以为一个“代码审查”子代理提供一个专门的 Prompt，指导它如何进行代码审查。

### 3.3. 注入机制

-   在 `_get_subagents` 函数中，当创建 `general-purpose` 代理或任何未提供自定义 `system_prompt` 的子代理时，这个 Prompt 会被用作 `create_agent` 函数的 `system_prompt` 参数。
-   它构成了子智能体执行其任务时的**基础世界观**。子智能体收到的 `HumanMessage`（来自 `task` 工具的 `description`）是在这个基础世界观之下被解释和执行的。
